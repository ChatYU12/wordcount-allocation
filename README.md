# 书稿字数分配工具

把一本教材/书稿的 PDF 和一张「谁要写多少字」的名单，自动排成可执行的编写分工表：
每人一段连续章节、标注页码范围、任务级不拆分、必要时自动安排「主编 + 副编」合作，
并直接导出带课时量与任务书的 Excel。

本机运行，不上传任何文件。界面是浏览器里的单页，解析与计算都在本地。

> **在线演示**：<https://chatyu12.github.io/wordcount-allocation/>
>
> GitHub Pages 上是**静态快照版**——界面、示例数据、分配结果都是真的，可以随便点；
> 但上传 PDF、重新分配、导入名单、导出 Excel 依赖本地 Python 后端，需要下载后运行（见下）。

## 使用流程

1. **导入书稿** —— 拖入 PDF，自动识别目录里的「模块 / 项目 / 任务 / 项目检测 / 岗位实践 / 能力拓展」，也兼容「第X章 / 第X节 / 单元 / 课题」结构。
2. **设字数口径** —— 每页字数 / 全书总字数 / 名单合计，三选一（见下文）。
3. **填名单** —— 上传 PDF 后会自动从**扉页识别编写人**（主编/副主编/参编）填进来；也可以手填或从 Excel 导入。**顺序就是书稿顺序**，也决定谁能和谁合作。
4. **核对章节页数** —— 可逐行改正，也可批量粘贴。
5. **生成方案** —— 得到分段表：角色、编写人、章节、页码、页数、字数、目标、偏差、课时。
6. **导出 Excel** —— 六个工作表：分配总表 / 按人汇总 / 章节明细 / 联合编写分工 / 编写任务书 / 计算说明。

## 一、字数怎么算

### 法定口径：版面字数

国家新闻出版署《图书质量管理规定》（新闻出版总署令第 26 号，2005-03-01 施行）附件第二条：

> 图书总字数的计算方法，一律以该书的版面字数为准，即：总字数 = 每行字数 × 每面行数 × 总面数。

同一条还规定：正文、目录、辅文**不论是否排字，均按一面满版计算**。

判断依据：[图书质量管理规定 · 中国政府网](https://www.gov.cn/zhengce/2021-12/08/content_5724645.htm)

### 整页图按 20% 折算

同一附件：**正文中的插图占一面的，按正文满版字数的 20% 计算字数。**

工具会自动识别「整页图」——文字少于 120 字且图像覆盖版面一半以上——并把该页权重降为 0.2：

```
有效页数 = 页数 − 整页图页数 × 0.8
```

页面上的「整页图按满版 20% 折算」开关可随时关闭（改为纯按页数计）。示例书中 294 页里有 2 页整页图，影响很小；图表书、图册差别就大了。

### 平均法：总字数 ÷ 正文页数

出版实务里最常用的是平均法，工具默认按这个口径算：

```
平均每页字数 = 全书总字数 ÷ 正文页数
某章字数     = 该章页数 × 平均每页字数
```

**正文页数不含**目录、扉页、前言、参考文献——这些不算正文。工具从目录解析出的章节区间得出正文范围，
参考文献单独识别并排除。

工具会直接显示算出来的平均每页字数。例如一本书 260,000 字、正文 200 页：

```
正文 200 页 → 平均 1300.0 字/页
项目一 1 页  → 1,300 字
任务一 5 页  → 6,500 字
任务三 14 页 → 18,200 字
```

只要每页字数相同，算出来的总数就一分不差。

### 三个字数入口，填哪个都行

| 你填的 | 工具怎么算 |
|---|---|
| **全书总字数**（推荐） | 按平均法分摊：平均每页 = 总字数 ÷ 正文页数 |
| 每页字数 | 直接按页数 × 每页字数，适合已知印刷参数时 |
| 勾选「用名单需求合计」 | 总字数 = 名单里所有人目标字数之和，再按平均法分摊 |

填了总字数就自动切到平均法。分摊用最大余数法，各单元与理论值最多差 0.5 字，总额一分不差。

## 二、分配规则

### 硬约束（不会违反）

1. **任务不可拆分** —— 一个任务/项目尾块整块归属某一段，不会出现半个任务分给两人。
2. **每人一段连续区间** —— 同一人在书中只出现一次，页码连续。
3. **全书完整覆盖** —— 不留空档、不重叠。
4. **项目检测 / 岗位实践 / 能力拓展** 跟随所属项目，合成尾部块，不单独发人。

### 拆分粒度：任务级 还是 分节级

导入书稿时有一个「**按小节拆分（偏差更小）**」开关，决定分配精度的上限。

| 粒度 | 最小单元 | 典型偏差 | 适用 |
| --- | --- | --- | --- |
| **任务级**（默认不勾） | 一个完整任务 | ±10% ~ ±45% | 严格不拆任务；书稿任务本身大小均匀时够用 |
| **分节级**（勾选） | 任务内按「一、二、三」分出的一节 | ±5% ~ ±10% | 任务大小悬殊（如某任务 55 页、别的只有 5 页） |

为什么会有差别：偏差下限由**可切点的密度**决定。所有人必须领连续区间，切点只能落在单元边界上。
如果某个任务是 55 页、而下一个人只该拿 38 页，这中间没有第二个切点，偏差就锁死在 +43%。

实测一本 200 页、9 人分配的书：

```
任务级      25 个单元（平均 8.0 页，最大 55 页） → ±43.36%
分节级      96 个单元（平均 2.1 页，最大 10 页） → ± 7.03%
```

分节级的切点来自正文里的「一、准备工作」「（一）视诊」这类标题，业务上一个小节本身
就是一个完整单元，比从任务中间硬切更自然。切出来的单元会带出分节标题，例如
`任务一 老年人健康标准和健康分级（一、老年人健康标准）`。

### 软约束（尽量满足）

- **主编可带副编合作** —— 一段由「主编 + 副主编」共担，两人目标字数相加后与该段实际字数比较。只有单人吃不下时才启用。
- **联合编写会标明各人负责的章节** —— 合作段内部按目标字数比例把任务分成前后两段，各自得到连续的页码范围。
  界面在合作段下方展开两行子行，列出每人的角色、章节、页码、页数和偏差；导出的 Excel 有独立的
  「联合编写分工」工作表。例如：

  | 段 | 姓名 | 角色 | 负责章节 | 页码 | 页数 | 分配字数 |
  |---|---|---|---|---|---|---|
  | 3 | 任兰梅 | 主编 | 项目二 躯体评估（任务二）；项目三 心理健康（项目首页、任务一） | 83–100 | 18 | 23,400 |
  | 3 | 朱娟 | 副主编 | 项目三 心理健康（任务二、任务三） | 101–111 | 11 | 14,300 |
  | 3 段合计 | | | 2 人共同完成 | | 29 | 37,700 |
- **合作段按目标比例切分** —— 不再均分。两人各拿多少按各自目标字数比例算，例如目标 6 万与 2 万的组合，段内按 3:1 分。
- **优先在项目边界切分** —— 切点落在项目之间比切在任务中间更「整」。

### 角色层级检查

行业惯例是主编 > 副主编 > 参编 的编写量。任务粒度受限时可能出现倒挂（参编拿到比副主编多的字），工具会提示：

> 角色层级倒挂：参编的平均分配字数高于副主编。任务不可拆时可能出现这种情况，建议调整名单顺序或允许拆分该章节。

这是**提示不是强制**——强行约束可能导致无解，最终由人决定。

### 求解方式

在「单元位置 × 人员前缀」上做动态规划，先二分出这本书**客观能达到的最小偏差**，再在该偏差内最小化总偏差（带项目边界偏好）。

## 三、公网访问（内网穿透，可选）

想在手机、或发给同事用，可以把本地服务通过 Cloudflare 隧道暴露出去。**两步：**

```bash
# 1. 带访问口令启动（不设 ACCESS_CODE 就是现在这样，本地不需要口令）
ACCESS_CODE=你的口令 PORT=8770 python3 app/server.py

# 2. 另开终端，建隧道（cloudflared 需先安装，见下）
cloudflared tunnel --url http://127.0.0.1:8770 --protocol http2
```

第二条命令会打印一个 `https://xxx.trycloudflare.com` 地址，任何人打开它都会先看到口令页，输对了才能用。口令可通过 `/logout` 退出。

### 装 cloudflared（macOS / Apple Silicon）

```bash
curl -L -o /tmp/cf.tgz https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-darwin-arm64.tgz
tar -xzf /tmp/cf.tgz -C ~/.local/bin && chmod +x ~/.local/bin/cloudflared
```

### 踩过的坑

- **ClashX / 代理软件的 TUN（增强模式）会把隧道流量拦死**：表现为 `failed to dial with quic: timeout` 或 `TLS handshake with edge error: EOF`。关掉增强模式（保留系统代理即可）就正常。
- 默认 QUIC 走 UDP 443，被拦时加 `--protocol http2` 走 TCP。
- 隧道地址是**临时的**：cloudflared 进程一停、电脑一关就失效，每次启动都是新地址。
- 这是免费隧道，不保证带宽和稳定性，只适合临时分享，不适合长期对外服务。

### 安全

暴露到公网意味着**拿到地址的人都能上传书稿**，务必设 `ACCESS_CODE`。口令不对时 `/api/*` 一律返回 401，页面请求跳转登录。

## 四、名单从哪来

### 单独上传扉页（图片或 PDF）

名单卡片右上角 **「上传扉页」**，可以直接传扉页的**截图 / 照片**，也可以传含扉页的 PDF。
工具用 macOS 自带的 Vision 框架做中文 OCR，**不需要装任何 OCR 依赖**。

识别后会按公司制度自动填好字数：

| 角色 | 制度字数 |
| --- | --- |
| 主　审 | 不承担编写，不分配 |
| 总主编 | 只署名，不分配 |
| 主　编 | 依次 **6 万 / 5 万 / 3 万**（第 4 位起按 3 万） |
| 副主编 | 各 **2 万** |
| 参　编 | 常规不分配；全书字数有余量时各 **1 万** |

参编的 1 万不是无条件给的：书稿解析出全书字数后，工具会算「全书可分配 − 制度需求 = 余量」，
够一位就发一位（按扉页顺序先到先得），界面上会显示还能给几位，并给一个「一键分配」按钮。

**版式还原**靠 OCR 的坐标：按 y 聚类成行、行内按 x 排序，才能把
「主　编　王春桃　龚建光　任兰梅」这种一角色多姓名正确拆开，也能处理角色跨行排列的情况。

OCR 的几类误差都有对策：

| 问题 | 对策 |
| --- | --- |
| 主审 → 主車（形近字） | 「主X」兜底匹配 |
| 副主编 → 主编（漏字） | 角色必须严格降级，重复出现即降一级并提示 |
| 角色与姓名黏成一格 | 按角色词前缀拆分 |
| 角色被拆成单字 | 相邻片段能组成角色词时合并 |
| 姓名内部空格（杨 丽） | 去空白后是 2–4 字姓名就合并回去 |

所有识别结果都会填进表格，**逐行核对后再生成方案**。系统不支持 OCR（非 macOS）时，
会提示改用 PDF 或手动录入。

### 从扉页自动识别（上传 PDF 后自动完成）

出版物的扉页/版权页一般长这样：

```
总主编　邹文开
主　编　夏　群　邓竹君　景　丽
副主编　汪　涛　卢振芝　欧唐燕　黄嘉嘉　刘洁俐
参　编　梁　锦　夏紫晴
```

工具会扫描前 12 页，按「角色词打头 → 其后是姓名 → 紧随的纯姓名行延续同角色」的规则解析，
自动处理全角空格、姓名中间的空格（`夏　群` → `夏群`）、跨行排列。

几点约定：
- **总主编默认不纳入分配**（通常只署名不写章节），但会在提示里告诉你识别到了谁
- 字数按角色给默认值（主编 6 万 / 副主编 4 万 / 参编 2 万），**必须自己核对调整**
- 遇到目录页会立即停止，不会把「项目检测」「岗位实践」这类词误认成人名
- 识别不准就直接改表格，或改从 Excel 导入

### 直接从 Excel 导入

名单卡片右上角「导入 Excel」，选 `.xlsx` 或 `.csv` 即可。不用改格式，工具会自己找表头：

- **表头可以在第几行都行** —— 前面有「《某书》编写名单」这种大标题、空行、合并单元格都不影响。
- **列顺序随意** —— 靠列名匹配，不靠位置。中间夹着部门、职称、备注也不影响。
- **列名认多种写法** —— 姓名 / 名字 / 编写人 / 作者 / 人员 / 编委；角色 / 职务 / 身份 / 岗位；需要字数 / 目标字数 / 分配字数 / 字数 / 工作量。
- **字数认多种写法** —— `60000`、`6万`、`6.5w`、`6千`、`12,000` 都行。
- **角色认关键词** —— 总主编 → 主编 → 副主编 → 参编依次判定，`副主编`不会误判成`主编`；认不出来的按参编。
- **自动跳过干扰行** —— 「合计 / 总计 / 小计 / 平均」这类的行不会被当成人。
- **可选「可合作」列** —— 填「否」表示此人不参与合作编写，留空视为可合作。

导入后会提示识别到多少人、用的哪个工作表、表头在第几行，逐行核对改完再生成方案。**原有方案会清空**，避免拿旧结果配新名单。

拿不准格式就先点「下载模板」，按模板填完导回来。

### 手填与微调

表格里可以增删行、上下移动、改任意单元格。上移下移很重要——**名单顺序决定书稿顺序**，也决定谁能和谁搭伴合作。

## 五、折合课时与编写任务书

### 折合课时

参数「每 1000 字折合课时」默认 1.0，按所在单位口径改。分配总表、按人汇总、编写任务书三处都会自动算出课时。

高校常用做法是「字数 → 课时量 → 绩效」，这一栏就是为了让表直接进入考核流程。

### 编写任务书

导出 Excel 的第 4 个工作表，可直接发给作者：

| 序号 | 编写人 | 角色 | 负责章节 | 页码范围 | 字数要求 | 折合课时 | 交稿时间 |
|---|---|---|---|---|---|---|---|

- **字数要求**给的是区间（按容差上下浮动），不是单点数字
- 末尾附「质量要求」「变更与退出」两段，以及签字栏
- 交稿日期在页面参数区填

质量要求与退出条款可在导出前自行调整（默认文本已按行业惯例写好）。

## 六、为什么偏差做不到 0

任务粒度决定精度，不是算法问题。示例书实际结果（总字数 360,000）：

| 段 | 编写人 | 页码 | 页数 | 字数 | 目标 | 偏差 | 课时 |
|---|---|---|---|---|---|---|---|
| 1 | 夏群 | 3–52 | 50 | 60,573 | 60,000 | +1.0% | 60.6 |
| 2 | 邓竹君 | 53–92 | 40 | 49,248 | 50,000 | −1.5% | 49.2 |
| 3 | 景丽 + 汪涛 | 93–162 | 70 | 85,199 | 80,000 | **+6.5%** | 85.2 |
| 4 | 卢振芝 | 163–191 | 29 | 35,705 | 40,000 | **−10.7%** | 35.7 |
| 5 | 欧唐燕 | 192–216 | 25 | 30,780 | 30,000 | +2.6% | 30.8 |
| 6 | 黄嘉嘉 | 217–238 | 22 | 27,085 | 30,000 | **−9.7%** | 27.1 |
| 7 | 刘洁俐 | 239–264 | 26 | 32,012 | 30,000 | +6.7% | 32.0 |
| 8 | 梁锦 | 265–280 | 16 | 19,699 | 20,000 | −1.5% | 19.7 |
| 9 | 夏紫晴 | 281–296 | 16 | 19,699 | 20,000 | −1.5% | 19.7 |

理论最小最大偏差 **±10.9%**。原因：中间那段任务块是 8/6/5/5/5/7/**18** 页，卢振芝要 4 万字（约 32 页），离他最近的可行切点是 29 页（−10.7%）和 36 页（+10.2%），中间没有第三个切点。

想更准，按性价比排序：

1. 把每页字数或全书总字数填成实际值；
2. 允许拆分最大的那个任务（本例 18 页的「帕金森病评估」）；
3. 名单里把想搭档的人调成相邻顺序。

页面横幅会直接告诉你这本书「客观可达到的最小偏差」是多少。

## 常见问题

**Q：导入的 Excel 认不出来？**
提示会告诉你识别失败的原因。最常见是**没有表头**（第一行直接写人），工具无法确定哪列是姓名——加上一行表头再导。其次确认「姓名」列标题就叫姓名或编写人、作者。

**Q：名单里有编辑、审稿人怎么办？**
导入时只认作者角色。责任编辑、审稿专家这类不计字数的角色请单独维护，别放进这张表。

**Q：目录识别不出来？**
书稿前 40 页需有目录页，形如「项目一 职业认知 …… 3」。失败时会提示，可用「批量录入」直接粘目录。

**Q：页码对不上？**
工具自动估计「印刷页码 ↔ PDF 物理页」的偏移。对不上就在章节表逐行改「起页 / 页数」。

**Q：整页图识别不准？**
判定条件是「文字 < 120 字且图像覆盖 > 55% 版面」。识别不准就直接关掉折算开关，或改章节表里的页数补偿。

**Q：可以多人同时用吗？**
服务默认监听所有网卡，同网段设备都能访问，各自的数据在各自浏览器里。想只本机用：`HOST=127.0.0.1 python3 app/server.py`。

**Q：数据会上传到哪？**
不会。上传的 PDF 解析完立即删除，名单和结果只存在于浏览器页面里。
